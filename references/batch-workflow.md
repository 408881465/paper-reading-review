# 形态 D：批量分层处理（N ≥ 30 篇，或需要增量追加）

## 1. 何时用形态 D

形态 A/B/C 都假定「你会把每篇都读透」。文献量一大，这个前提就不成立了：

| 信号 | 说明 |
|---|---|
| 输入 ≥ 30 篇，或总页数 ≥ 300 | 逐篇出详版（1500–10000 字/篇）在时间与成本上都不成立 |
| 用户说「文献比较多」「先过一遍」「后期还会加新文献」 | 需要的不是一次成稿，而是一份**可增量维护的语料资产** |
| 语料里混着专著、学位论文、政策文件、图片型 PDF | 单篇解码的假设立场失效，必须先分流再处理 |

**形态 D 不是一个新模板，而是一层外壳**：它负责「登记 → 判重 → 抽文本 → 分档 →
派活 → 汇入 RCOS」，档位内的单篇产出仍用形态 A 的模板，主题层仍用形态 B/C。
**先读本节，再回到 SKILL.md 主流程。**

## 2. 四档分流判准

分档回答的是「这篇值得花多少力气」——**不是「这篇好不好」**。

| 档位 | 判准（满足任一即入档） | 单篇产出规格 |
|---|---|---|
| **T1 核心** | ① 与课题的**核心构念**有直接对话（如课题研究"协同机制"，则该文明确提出协同/联动/衔接机制）；② 提供了可借用的分析框架或类型学；③ 与课题研究对象同层级（同为高中/同类校本课程）；④ 领域内被反复引用的奠基文 | 形态 A **详版（1500–10000 字）+ 一页速览** |
| **T2 重要** | 与课题同一主题域，但只覆盖其中一个侧面；或提供了可比较的实践样本 | **解码卡**（一页，见 `assets/decode-card-template.md`） |
| **T3 背景** | 主题相关但结论宽泛（同类文章的重复表述）、或仅为政策背景 | 只入 **RCOS 整合表**一行 + 一句话定位，不出单篇文档 |
| **专著/学位论文** | 页数 > 60，或本身是系统论述 | **章节级解码卡**：只对与课题相关的章做完整解码，其余章只记标题与定位 |
| **政策文件/指南/标准/教材** | 非研究文献，无研究设计 | 单列「政策与依据」清单（文号、发布机构、时间、与本课题的关系），**不做学术批评点** |
| **去重-重复** | sha1 相同 | 只登记，不处理 |

**T1 占比参考**：T1 宜控制在总数的 10%–15%。若 T1 超过 20%，多半是判准放宽了——
「与课题相关」不是「被我引用」的理由。

**分流时不许写成「有一定参考价值」。** 判定口径统一用 `review-workflow.md`
第 5 节的四值：**纳入（核心）/ 纳入（背景）/ 暂不纳入 / 待核查**，并给出判据。

## 3. 登记表与状态机

登记表（`assets/triage-registry-template.csv`）是形态 D 的唯一真相来源。
每行一篇，**行一旦写入就不再删改身份字段**（编号/文件名/sha1/源路径）。

```
发现 ──→ 去重判定 ──→ 已抽文本 ──→ 已分流 ──→ 已解码 ──→ 已入RCOS ──→ 已入综述
             │                        │
             └→ 去重-重复（跳过）      └→ 需OCR（图片型，先 OCR 再用 attach 回流）
                                      └→ 待其它提取器（暂无抽取器的格式，如 pptx）
                                      └→ 待核查（同名不同内容、元数据缺失）
```

### 3.1 三条支线的收口动作（缺一个闭环就断）

| 支线 | 怎么收口 | 谁做 |
|---|---|---|
| **需OCR** | 用 OCR 工具抽出文本后，`sync_corpus.py attach <表> <编号> --text <文件>`。它会写 `文本路径`／`字符数`／`解码状态=已OCR`，**不碰**档位与纳入判定 | 人跑工具 + 脚本挂载 |
| **待其它提取器** | 该格式暂无抽取器（pptx 等），需人工用其它工具转文本，再同样用 `attach` 挂载 | 人 |
| **.docx** | **已有抽取器**：`extract_docx_text.py`，`batch_extract.py` 会**自动走它**，无需人工介入。★注意 .docx **无固定页码**，产出不含 `PAGE` 标记，回指基准是**章节名** | 脚本 |

> **为什么要有 `attach`**：状态机写着"先 OCR 再回主流程"，但 2026-10-08 实测
> `sync_corpus` 只有 `init/scan/status` 三个子命令、**回流没有任何入口**——
> 抽好的文本只能手工去改登记表，既易写错，也绕过了"身份字段不得改"的约束。

`解码状态` 是流程控制字段，`档位`/`纳入判定`/`主题分类`/`相关度` 是**人（或读文队友）
的判断结果**，`页数`/`字符数`/`文本路径` 是脚本回填的结果。三者不要互相覆盖。

## 4. 增量同步协议（后期还会加新文献时）

**四条纪律**：

1. **只追加，不重算**。已读文献的解码卡、RCOS 行、综述段落永不因为新文献入库而重写。
2. **判重要分两层**，只做一层必出错：
   - **文件层**（sha1 逐字节）——抓完全相同的文件；
   - **文本层**（抽取文本的哈希）——抓「同一篇被重新保存 / 换过页眉元数据」的情况。
     这类文件字节不同、文件层判不出来，但内容一模一样；只做文件层判重的后果是
     **对同一篇文献读两遍，写出两份互相矛盾的解码卡**（2026-10-07 实测：161 篇里
     有 5 对属于此类）。
   `batch_extract.py` 抽完文本会自动报告文本层重复对；**脚本只报告，取舍由人定**
   （保留文件名最干净的一份，另一份标「版本重复，取 Lxxxx」并跳过）。
3. **同名不同内容要报警，不是静默合并**——CNKI 下载最容易出现「标题相同、年份不同」的两篇。
   注意：`sync_corpus.py` 的同名判定只按**文件名归一**，它报「同名不同内容」时
   **尚未**确认内容不同，必须等文本层比对结果，不要据此直接删掉一篇。
4. **增量出增补说明**（`v2 增补说明`），说明新增了哪些、进了哪个主题、是否改变原结论。
   **改变原结论必须显式写出来**——这是增量维护最容易被掩盖的错误。

标准动作：

```bash
# 1) 新文件先放进投放入口（建议：<项目>/新增文献/，不要直接往原始目录里撒）
# 2) 同步登记表（只追加新 sha1）
python3 scripts/sync_corpus.py scan 01_文献总表/文献总表.csv --source 新增文献/
# 3) 只为新行抽文本（已抽的跳过）
python3 scripts/batch_extract.py --registry 01_文献总表/文献总表.csv --outdir 02_文本
# 4) 看新增了哪些、还差哪些
python3 scripts/sync_corpus.py status 01_文献总表/文献总表.csv
# 5) 按第 2 节判准给新行分档，再派活；旧行不动
```

### 4.1 编号稳定性：**新增文献不得改变原有编号**

`编号`（`L0001`…）是**扫描顺序派生**的，而技能纪律说它是**身份字段**
（§3「行一旦写入就不再删改身份字段」）——产出文件名（`T1-L0030-…md`）、RCOS 行、
解码卡里到处嵌着它。**编号一错位，它们就全部指向别的文献，且不会有任何报错。**

**两条路径都已保证保号**（2026-10-09 实测）：

| 做法 | 行为 |
|---|---|
| **增量 `scan`**（推荐） | 既有行编号**不动**，新文件**追加**新编号。实测：新增一个排序在**最前**的文件，既有 `L0001–L0003` 不变，新文件得 `L0004`。反复 scan 幂等；源目录删文件时旧行**保留**（不自动删） |
| **重建**（`init --force` + `scan`） | ★**同样保号**：`init --force` 会把「编号 ↔ 文件」映射写入 `登记表.csv.idmap.csv`，`scan` 按**文件名**（其次 sha1）复用旧编号，新文件才拿新号。实测两次重建后 `L0001–L0003` 始终不变、新文件依次得 `L0004`／`L0005` |

**为什么会错位（修复前的失效模式，作为背景）**：编号按"路径排序后依次编号"派生，
所以**插入一个排序在前的新文件会让后续编号整体后移一位**。用户明确要求
"后续增加新文件，不要改变原有文献编号"，故改为**继承式分配**。

**仍须注意**：

1. **不要改文件名**——sidecar 按文件名（其次 sha1）匹配，改名会使旧编号失配，
   该文件会获得新编号（内容未变，但身份变了）。
2. **sidecar 与登记表是一对**：`登记表.csv.idmap.csv` 要一起备份、一起移动。
   丢了它，重建会退回"按扫描顺序重新编号"。
3. **跨机器/跨目录各改一份表再合并**——本技能不提供合并工具，**这是它的边界**。

## 5. 中文实践类／政策解读类论文的解码适配

大量中文期刊文是「校本实践总结」「区域经验介绍」「政策解读」，十密码里
**至少三到四条天然缺失**。硬填会写出假内容，这是形态 D 最大的失败模式。

**先承认缺失，再找替代路径**：

| 密码 | 这类文章的常见情形 | 合规写法 |
|---|---|---|
| 作者提出的主要问题 | 常藏在「问题的提出」「现实困境」段，不是问句 | 转写为问句，标注「本文评述据第 X 页归纳」 |
| 现有文献综述 | 往往只是「政策罗列 + 名词解释」，不是学术综述 | 如实写「以政策梳理代替文献综述，未与具体研究对话」 |
| 现有文献批评 | **大多完全没有** | 写「作者未对任何前人文献提出批评」——这本身就是重要发现 |
| 空白 | 极少明示 | 可写「作者未指出空白」，再从「作者选取的切口」反推隐含空白，**必须标注为本文评述的推断** |
| 理论依据 | 常无理论，只有政策依据或经验依据 | 区分「理论依据（无）／政策依据（文号）／经验依据（校情）」三栏，不要混为一谈 |
| 研究结果 | 无数据，只有成效叙述 | 写「成效证据类型：教师自评／学生作品／获奖／满意度问卷」，并说明**无对照、无法归因** |
| 相反的研究发现 | 几乎必无 | 写「未报告任何相反或失败案例」——这与课题的"实施路径"直接相关，是真实短板 |

**实践类论文的批评点替代四条**（比「方法有待加强」具体，且可核对）：

1. **可操作性定义缺失**——"跨学科协同""AI 素养"等核心构念只用口号式表述，
   未给出可观察指标，导致他人无法复现。
2. **样本代表性**——单一学校／单一年级／单一教师的一轮实践，无法外推到
   "普通高中"这一层级；作者若声称可推广，即为推断越界。
3. **成效证据不闭环**——以自评、作品展示、获奖替代前后测或对照，
   作者却使用了因果措辞（"显著提升了……"）。
4. **时点局限**——依据 2025 版课标／2025 年指南写作的文章，
   其"实施效果"必然早于课标落地，属于**预测而非实证**。

**专著/学位论文的章节级处理**：只对与课题相关的章出解码卡（通常 2–4 章），
其余章在卡上列标题 + 一句定位即可；**不要**为了完整性把 200 页书压缩成一张卡，
那会把最该保留的论证结构压掉。

### 5.1 回指基准：印刷页码 vs PDF 序（必须一次说清）

抽取文本的标记是 `===== PAGE n =====`，其中 n 是 **PDF 序**；而学术写作引用的是**印刷页码**。
CNKI 期刊页前常有栏目页、学位论文前有封面与摘要，因此**偏移量逐篇不同**
（实测 +13／+37／−8／+39），**无法统一换算**。不处理这一层，产出会
**全部通过格式自检、却一条引用都无法机械核对**（2026-10-07 实测：86 份产出中 13 份
用印刷页码，偏移各异，lint 只数 locator 个数，查不出基准错位）。

`batch_extract.py` 已自动检出偏移并标注：

```
===== PAGE 1 ===== [印刷页码 p.14]
```

**四条操作规则**：

1. **正文引用一律用印刷页码**（读者按 p.14 才查得到原文）；核对时用标注换算。
2. **没有标注就回指章节名**——页码被拆成「4 0」这类形态、或学位论文前段本无页码时，
   工具检不出恒定偏移；此时凭空给页码就是编造。
3. 检偏移**必须看页首/页尾各若干行**，不能只看第一行：CNKI 页首常有「FOCUS／本期策划」
   这类栏目眉，只看首行会整体漏检；外推页码 < 1 时**不标注**（否则学位论文会标出 p.-7）。
4. **专著/学位论文的章节级卡另有规格**（★**首行或文件名里必须有「章节」二字**，
   否则会被判成一页卡而报"超限"——两种卡的字数区间差一倍；实测见
   `assets/decode-card-template.md` 顶部的说明）：`lint_review.py --form chapter-card`（400–5000 字），
   不要套 T2 卡的 2500 字上限，也不要为压字数把 200 页书压成一张卡。

5. **回指基准必须能被读者在文本内一步复算，且写明派生自哪一处可见印记。**
   这是本项目付出一次系统性返工才换来的规则（2026-10-07）：自动推断的印刷页码
   **看起来自洽**（偏移恒定、页序连续）却整体错，因此——

   | 允许进入产出的基准 | 不允许 |
   |---|---|
   | `文本 ===== PAGE n ===== ↔ 印刷页 p.(n+K)`，且写明 K 来自哪一处可见印记（页眉页码／页脚数字／文章编号／卷期页范围） | 「系统已加注印刷页码，可逐处核对」——**依赖一个读者在文本里看不到的对象** |
   | 逐篇核对过的 K（例：某刊页眉印 42/43/44 → K=+41） | 用一个统一偏移套用到所有文献 |
   | 无印刷页码者退到 **形式 B**：按章节名或标记页，并注明原因（在线首发／**开放获取文章自带 `Page N of M`**／报纸版次／docx） | 凭"看起来像"推算印刷页 |

   **一句话判据**：读者只拿这份产出和 `02_文本/`，能不能**一步步算**出被引的那一页？
   能，才算可核对；不能，就退到形式 B。

### 5.2 「档位」是产出规格，不是「是否读过」

批量作业里最容易混淆的两个字段：

- **档位**（T1/T2/T3）＝ 产出规格与证据权重；
- **产出形式**（单篇详版／章节级／解码卡／仅入表）＝ 实际产出物。

队友读得比档位要求更多是允许的（T3 也可能被通读），因此**在综述里引用 T3 编号作证据时，
必须就地标明证据地位**（「（T3，仅按题录与摘要定位）」或「（T3，已通读全文但按背景使用）」）——
不得既不声明、又当页码级证据使用。

⚠️ **不要把「档位」和「产出形式」合并成一个字段**：>60 页的学位论文既是 T1（证据权重高）
又要按章处理（产出形式＝章节级），合并后归一映射会把它的 T1 标记吃掉
（2026-10-07 实测：两篇 T1 因此从统计里消失，T1 数从 18 掉到 16）。

⚠️ **负责人的裁定必须单独落一张表，并在合并脚本里最后套用**：否则每次重跑合并，
裁定都会被队友分流表里的旧档位覆盖（实测：升 T1 后一跑合并就退回原值）。

### 5.3 形态 D 的 RCOS 最小列集（各队表结构必须一致）

`build_review.py` 只强制 作者／年份／现有文献综述／研究结果 四栏，于是各队会各自发明表结构——
2026-10-07 实测：四张分表出现**四种编号放法**（独立「编号」列／写在「序号」列／写进标题开头／
完全没有编号）与三种「批评点」写法，合并时一度把不同队的第 1 行错并成同一篇（71 条假冲突）。

**形态 D 建议统一用这张最小列集**（其余列可留空，但列名不得改）：

```
编号,作者,年份,标题,来源,现有文献综述,现有文献批评,空白,理论依据,
研究结果,一致的研究发现,相反的研究发现,作者给出的答案,未来研究建议,
批评点,待探讨的相关问题,明显的遗漏点,能否理顺,主题分类,一句话定位
```

两条硬要求：
1. **必须有 `编号` 列**（Lxxxx），且每行只对应一篇——合并、对账、回指全靠它。
   不要把编号塞进「序号」或标题里。
2. **`理论依据` 列不可省**。它在校验器里不是必需栏，但「空白必配理论依据」是本技能的核心纪律；
   表里没有这一栏，写综述时就会退化成"指出空白却不说明怎么补"。
   实测四张分表全部缺这一栏，只能靠在综述正文里补，属可避免的返工。

### 5.4 引文保真：OCR 噪声与跨页引文**不作美化**

抽取文本来自 PDF，必然带噪声。2026-10-07 本项目在**多处独立**遇到同一类问题：
两位页码被抽成相邻两个单数字记号（`80` → `0`、`8`）、竖排页脚（`1 2 1`）、全角字符、
以及最典型的一处——某文件 OCR 把「学校**间**」识别成「学校**同**」。

**五条纪律**：

1. **逐字引用，不作美化。** 源文本写「学校同」，就引「学校同」并就地加注〔应为「学校间」〕；
   **不得静默改正**。理由：读者拿同一份 `02_文本/` 复核时，改过的引文会"查不到"，
   反而让人怀疑整份产出；加注则既诚实又可核。
2. **跨页引文要说明。** 引文跨 `===== PAGE n =====` 标记时，**去掉页标记后必须逐字连续**；
   核验脚本若因页标记而报"引文不匹配"，那属**工具假警报**，不得为了"匹配"而改动原文。
3. **核验必须记录命中率与例外。** 例如「15/15 命中」「14/14 命中，其中一条跨页断开，
   去页标记后逐字命中」。**不允许只写"已核对"**——没有命中率的核对无法追责。
4. **复现 ≠ 归属：合并句式不得错配引文主语。** 引文逐字抄对、却把 A 文件的话说成 B 文件的，
   同样是不保真。**2026-10-08 实战事故**：把「信息科技课标把人工智能列为六条逻辑主线之一」
   与「技术与工程课标要求以项目、主题、任务等方式组织跨学科学习」**并为一句**——
   「**两门国家课程标准分别把人工智能列为"六条逻辑主线"之一**、要求"……组织跨学科学习"」。
   两句引文各自逐字无误，**第 1–3 条全部通过**，但「**分别**」把两个谓语捆在同一主语上，
   会被读成「两门课标都列了六条逻辑主线」；回原文核：信息科技课标「六条逻辑主线」**3 处**，
   技术与工程课标「逻辑主线」**0 处**。
   **检查动作**：一句里出现两个及以上来源，且带「**分别／均／都／两门／三份／各自**」这类
   共享主语的词时，**必须逐来源回原文确认定语与谓语各修饰谁**；并列分句宁可拆开写，
   也不共用主语——省下的几个字不值得赔上归属。
5. **压缩之后必须回核归属。** **压缩与合并是引文错误的高发环节**（上一条即发生在此处），
   因为省字首先省掉的就是主语与限定语。**任何一次压字数或改写引文所在句之后，
   必须重新逐条回原文复核归属，不得沿用压缩前的核验结论**——
   **核验结论只对它当时的那一版文字有效**。

6. **多栏排版的 OCR 会打乱阅读顺序——这类文本不可直接引用。** OCR 按行的
   水平位置输出，双栏页面上会把**左栏末行与右栏首行接成一句**。2026-10-08 实测：
   一份双栏期刊扫描件的 OCR 结果里，「作；二是加强大学教师与中小学教师、科任教」
   与「我校教师教育创新实验区建设工作已由"东北区域运行"走向…」被串读成一段，
   单看文本完全通顺，**只有回原 PDF 对照才发现串栏**。
   **处置**：凡来源是扫描件／多栏排版的引文，**一律回原 PDF 逐字核对**；
   核对不便时按 §5.4 第 1 条就地加注（如〔原为双栏排版，OCR 行序有串栏，此处按原 PDF 校读〕），
   **不得按 OCR 文本直接引**。

7. **图表／流程图类图片的 OCR 产出**不是正文，**不可直接引用**。OCR 按行的水平位置
   输出，流程图会得到一串**散点式标签**（实测课题技术路线图：得到「研究进程」「(时间线索)」
   「阶段一」「研究内容一」这类孤立词，**不成句、没有连接关系**），且**相邻数字极易粘连**
   （实测 `2027.2—2027.8` 被读成 `2027.22027.8`）。
   **处置**：图片型输入（`需OCR`）经 OCR 后 `attach` 回来的文本，只作**位置索引**用；
   凡要引用其内容，一律**回原图逐字核对**，并在产出里写明"内容据原图"。
   若该图是本课题自制的（如技术路线图），**不要引 OCR 结果**——直接引原图或原始文稿。

**判据一句话**：读者只拿这份产出和 `02_文本/`，**能否复现这段引文，并指认它出自哪一份文件的哪一条**？
两条都能，才算保真。（只做到第一条，就会漏掉第 4 条那类错误。）

## 6. 并行分工与写作用域

批量处理必然要分头读。分头读的失败模式不是读错，而是**互相覆盖**与**判断口径漂移**。

- **按主题切分，不按页码切分**。每人负责一个或几个主题的**全部**文献，
  写**各自独立的目录/文件**（如 `03_解码卡/主题3-跨学科协同/`）。
- **口径先行**：开工前把第 2 节判准与第 5 节替代路径**原文发给每个读文人**，
  并在样本文献上先做 2–3 篇对齐，再全面铺开。
- **T1 详版与 T2 解码卡不交叉**：一篇文章只由一个读文人负责，写一个文件。
- **汇总者不重读原文**：只读解码卡与 RCOS 行做主题重组（这正是 RCOS 存在的意义）；
  汇总者怀疑某条时，回指到原文页码核对，而不是凭印象改写。
- 发现判断冲突（两人对同一篇分档不同）→ **回到第 2 节判准逐条对**，
  不以资历或先到先得定胜负。

### 6.1 登记表是**共享单点**——先看这一节再并行

上面五条管的是"各人写的散文"，但**真正的覆盖风险在登记表**。所有脚本都是
「整表读入 → 内存改 → 整表写回」，而 `batch_extract` 的窗口**从加载一直持续到
整批抽完**（实测 30 篇约 5–10 秒，上百篇可达数分钟）。2026-10-08 用真实文件
确定性复现两例，**两例都是技能的推荐用法**：

| 场景 | 后果 |
|---|---|
| 甲跑 `batch_extract`，乙同时 `attach` 挂 OCR 文本 | 乙的状态与备注**被清空** |
| 甲乙各 `scan` 自己的目录（§6 第一条就是这么规定的） | **甲的登记全部消失**（5/10），且**双方退出码都显示成功**，编号还撞成同一批 |

**已在脚本层修好**：`save_registry` 保存前比对文件指纹，发现被别人改过就
**重新读取并按编号逐格三方合并**，而不是整表覆盖。规则：

- 我们改过的格 → 用我们的；我们没改的格 → 保留他人的；
- **双方都改且不同 → 保留磁盘（他人后写的）**，并在 stderr 报冲突格；
- 他人新增的行原样保留；我们新增的行追加；
- **编号撞车**（双方各自新增却分到同一编号）→ 我们那行**让位重编号**，
  对方那一行的身份字段不动。

**并行时仍须遵守**：

1. **`scan` / `attach` 尽量串行**——这两条命令窗口短，串行成本几乎为零；
   真要同时跑，看 stderr 有没有"检测到并发写入"。
2. **`batch_extract` 期间不要另开写操作**。它窗口最长，虽然现在会合并，
   但合并只保护**其它行**；同一行同一格被双方都改时，保留的是磁盘版
   （即后写的那个），**先写的那个会被丢掉**。
3. **不要手工编辑登记表**（Excel/编辑器）与脚本同时进行——手工保存是纯覆盖，
   没有合并逻辑。要手工改就先停脚本。
4. 合并只在**同一台机器、同一个文件**上成立。多人各拷一份表分头改，
   再想合起来——本技能不提供合并工具，**这是它的边界**。

## 7. 质量门禁

形态 D 产出多、容易在数量上"看起来很完整"。出稿前必须全过：

| 门禁 | 检查方式 |
|---|---|
| RCOS 完备 | `python3 scripts/build_review.py rcos 07_整合表/RCOS整合表.csv` 退出码 0 |
| 登记表无悬挂 | 每行的 `解码状态` 与 `产出文件` 一致（已解码必有文件；跳过必有理由） |
| 回指可核对 | 抽查每份解码卡/详版的 3 处页码引用，回原文比对 |
| **引文归属** | 多来源并列句逐来源回核；**压缩/改写引文所在句后必须重核**（§5.4 第 4、5 条） |
| 中文密码名 | `python3 scripts/lint_review.py <文件>` 缩写残留为 0 |
| **产物卫生** | 同一 lint 命令报 `hygiene` 为 0（HTML 实体、`\1` 字面泄漏，见 §8.3） |
| 空白必配理论依据 | 综述里每个「空白」小节后面必须有「理论依据」 |
| 不做洗衣店接衣单 | 主题综述不得按作者年份铺陈；lint 脚本给出预警 |
| **术语与称谓** | 同义异名／同名异义／称谓漂移**三查全过**（§8） |
| 增量可复现 | 再跑一次 `sync_corpus.py scan`，输出应为「无新增」 |

**「读完了」不等于「读到了」**：T3 只入表是合法的取舍，但必须在总报告里写明
「T3 文献未逐篇精读，仅按题录与摘要定位」——不得把 T3 的题录包装成读过的证据。

## 8. 交付前一致性三查

形态 D 的产出会**被反复压缩、改写、合并**（往申报书/总报告里收），而**压缩正是术语事故的高发环节**。
下面三条都出自 2026-10-08 的真实事故，**各查一次，不能省**。

### 8.1 查同义异名（同一概念多处不同名）

读者会以为你说的是两件事。**成因**：不同轮次各自造词，或为避开敏感表述换词，却没回改前文。

| 事故 | 表现 | 处置 |
|---|---|---|
| 「教研时间入课表」vs「教研时间统筹」 | 同一机制在目标/内容/创新点三处三个名字 | 定一个正式名，全文替换 |
| 「教学任务认定」vs「工作量」 | 诊断清单与机制清单不同名，读者看不出两步怎么接上 | 让它们**同词根**：「教学任务**承担**」（诊断）→「教学任务**认定**」（机制） |

**动作**：列一张**术语表**（正式名｜简称｜禁用别名），交付前对全文扫一遍禁用别名。

### 8.2 查同名异义（同一个词在不同语境含义不同）

**不要盲目全局替换**——同一词在两种语境下可能是两个概念。

| 事故 | 语境 A | 语境 B | 处置 |
|---|---|---|---|
| 「工作量」 | **成本侧**：成本—效果分析要的真实投入工时 → **保留** | **制度侧**：是否被承认为可计入的任务 → 改为「教学任务承担」 | **按语境分别处理**，不做全局替换 |

**动作**：全局替换前，先看每一个命中点的**上下文**。全局替换是最容易制造新错误的操作。

### 8.3 查称谓漂移（角色变更后旧文本指向反转）

**最隐蔽的一类**：句子一个字没改，错在它指向的人变了。

**事故**：底本里「课题负责人」**就是**技术与工程教师；后来负责人变更为另一位（历史学科）校长、
原负责人转为「主要参与及实施者」。于是底本带来的那句
「4 个班级的技术与工程课程均由**课题负责人**统一主讲」
——**字面读成了「历史教师主讲技术与工程」**。

**动作**：
1. 维护一张**角色对照表**（角色｜姓名｜学科/身份｜职责），角色变更后**逐处检查含该称谓的句子**；
2. 凡「由**负责人**主讲/负责/主持」这类**以角色指代人**的写法，在角色可能变动时，
   **一律改写成实名＋角色括注**（如「由**汤铭**（课题主要参与及实施者，技术与工程）统一主讲」）。

### 8.4 查产物卫生（脚本引入的污染）

生成/改写脚本会**静默**把两类垃圾写进正文，人眼极难发现：

| 污染 | 形态 | 来源 |
|---|---|---|
| HTML 实体 | `&#x7684;`（＝「的」）、`&#x4EE5;`（＝「以」） | 某些库/工具把非 ASCII 转义后未回转 |
| 反斜杠引用字面泄漏 | `\1`、`\2` 出现在正文行首或紧贴汉字处 | `re.sub` 的替换体写成 `r"\1" + text`（而非函数），`\1` 被当字面量输出 |

**动作**：`python3 scripts/lint_review.py <文件>`——本技能已内置 `hygiene` 规则自动扫这两类
（见 `scripts/lint_review.py`）。**交付前必须为 0**。

**共同成因**：**自动化改写没有回头核**。所以三查的正确时机是**每一轮自动化改写之后**，
而不是只在最后一遍——最后一遍时，你已分不清哪句话是哪一轮写的。

## 9. 收口：总报告（形态 `report`）

形态 D 跑到最后**必须出一份总报告**，它是唯一能回答"这一批到底读成什么样了"的产出，
也是 T3 免责声明的落点。规格与必填节见 `assets/report-template.md`（下限 1200 字）。

三条硬性纪律：① 第 1 节「覆盖与精读声明」不可省，T3 部分必须写明
"未逐篇精读，仅按题录与摘要定位"；② 第 5 节「一致性三查」要给结论而不是"已检查"
（见第 8 节）；③ 所有计数必须能从登记表复算，并与 `sync_corpus.py status` 输出一致。
